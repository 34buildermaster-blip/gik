## 1. ภาพรวมระบบและสิทธิ์ผู้ใช้งาน

ระบบแบ่งผู้ใช้งานเป็น 3 บทบาทหลัก

| บทบาท | หน้าที่หลัก | ขอบเขตสิทธิ์ |
|---|---|---|
| Admin | บริหารระบบและตรวจอนุมัติข้อมูล | เข้าถึงทุกโครงการ ผู้ใช้ เนื้อหาเว็บไซต์ การตั้งค่า และประวัติกิจกรรม |
| ผู้ตรวจหน้างาน | ดูแลโครงการที่ได้รับมอบหมาย | ดูเฉพาะโครงการที่ตนรับผิดชอบ เพิ่มอัปเดตหน้างานและรายการปัญหา แต่อนุมัติเผยแพร่เองไม่ได้ |
| ลูกค้า | ติดตามโครงการของตนเอง | ดูเฉพาะโครงการที่ Admin ผูกกับบัญชี เห็นเฉพาะอัปเดตที่อนุมัติแล้ว เอกสารที่เปิดให้ลูกค้า และปัญหาที่กำหนดให้มองเห็น |

### ตารางสิทธิ์รายโมดูล

| โมดูล | Admin | ผู้ตรวจหน้างาน | ลูกค้า |
|---|:---:|:---:|:---:|
| แดชบอร์ด | ทุกโครงการ | เฉพาะงานที่มอบหมาย | - |
| จัดการผู้ใช้และสิทธิ์ | จัดการ | - | - |
| โครงการ | สร้างและจัดการ | อัปเดตโครงการที่มอบหมาย | ดูโครงการของตน |
| ขั้นตอนและน้ำหนัก | จัดการ | ดูและเสนอข้อมูลผ่านอัปเดต | ดู |
| อัปเดตหน้างาน | จัดการและอนุมัติ | สร้างและส่งตรวจ | ดูรายการอนุมัติแล้ว |
| เอกสาร | จัดการ | ดูตามสิทธิ์โครงการ | ดูเอกสารที่อนุญาต |
| ปัญหาหน้างาน | จัดการ | สร้างและอัปเดต | ดูรายการที่อนุญาต |
| เนื้อหาเว็บไซต์ | จัดการ | - | - |
| การแจ้งเตือนและโปรไฟล์ | ใช้งาน | ใช้งาน | ใช้งาน |
| 2FA | เปิดได้ | เปิดได้ | เปิดได้ |

หลักการสำคัญของระบบ

- ลูกค้าไม่เห็นฉบับร่าง รายการรอตรวจ หรือรายการที่ Admin ส่งกลับแก้ไข
- ผู้ตรวจหน้างานเห็นเฉพาะโครงการที่ได้รับมอบหมายเป็นผู้ดูแล
- เปอร์เซ็นต์รวมของโครงการคำนวณจากน้ำหนักและความคืบหน้าของแต่ละขั้นตอน
- การลดเปอร์เซ็นต์ หรืองานไม่ผ่านการตรวจ ต้องระบุเหตุผล
- การแจ้งลูกค้าเกิดหลัง Admin อนุมัติอัปเดตแล้ว
- การเพิ่ม แก้ไข ลบ และอนุมัติรายการสำคัญถูกบันทึกในประวัติกิจกรรม

## 2. โมดูลการเข้าสู่ระบบและความปลอดภัย

### ผู้มีสิทธิ์

ผู้ใช้งานทุกบทบาท โดยแต่ละบทบาทมีหน้าเข้าสู่ระบบแยกกัน

### การเข้าสู่ระบบ

1. เปิดหน้าสำหรับบทบาทของตนเอง ได้แก่ ลูกค้า ผู้ตรวจหน้างาน หรือ Admin
2. กรอกชื่อผู้ใช้หรืออีเมล
3. กรอกรหัสผ่าน
4. เลือกจดจำการเข้าสู่ระบบเมื่อต้องการ
5. กด `เข้าสู่ระบบ`
6. หากเปิด 2FA ระบบจะขอรหัสจาก Authenticator หรือ Recovery Code เพิ่มอีกหนึ่งขั้น

### การสมัครบัญชีลูกค้า

1. เปิดหน้าสมัครสมาชิก
2. กรอกชื่อ ชื่อผู้ใช้ อีเมล และรหัสผ่าน
3. ระบบสร้างบัญชีบทบาทลูกค้าเท่านั้น
4. หลังสมัคร ลูกค้าจะยังไม่เห็นโครงการจนกว่า Admin จะผูกบัญชีกับโครงการ

ในงานจริง แนะนำให้ Admin ตรวจสอบตัวตนและอีเมลของลูกค้าก่อนผูกข้อมูลโครงการ

### การกรอกรหัสผิดและการล็อกบัญชี

- ระบบอนุญาตให้ลองผิดได้ 5 ครั้ง
- เมื่อครบ 5 ครั้ง บัญชีจะถูกล็อกชั่วคราว 60 วินาที
- Admin สามารถปลดล็อกก่อนครบเวลาได้จากโมดูลจัดการผู้ใช้งาน
- ระบบแสดงข้อความผิดแบบกลาง เพื่อไม่เปิดเผยว่าชื่อผู้ใช้หรืออีเมลใดมีอยู่ในระบบ

### ลืมรหัสผ่าน

1. กด `ลืมรหัสผ่าน?` ที่หน้า Login
2. กรอกอีเมลของบัญชี
3. เปิดอีเมลและกดลิงก์ตั้งรหัสผ่านใหม่
4. ตั้งรหัสใหม่อย่างน้อย 8 ตัวอักษร โดยมีตัวอักษรและตัวเลข
5. ลิงก์มีอายุ 15 นาที

หมายเหตุ: ระบบ Production ต้องตั้งค่า SMTP ก่อนจึงจะส่งอีเมลจริงได้

### รหัสผ่านชั่วคราว

- Admin สามารถออกรหัสผ่านชั่วคราวให้ผู้ใช้ได้
- รหัสผ่านชั่วคราวแสดงบนหน้าจอ Admin เพียงครั้งเดียว
- Session เดิมของบัญชีนั้นจะถูกยกเลิก
- ผู้ใช้ต้องตั้งรหัสผ่านส่วนตัวใหม่ก่อนเข้าใช้งานส่วนอื่นของระบบ

## 3. โมดูลพื้นที่ลูกค้าและการติดตามโครงการ

### ผู้มีสิทธิ์

ลูกค้า

### หน้ารวมโครงการของฉัน

แสดงเฉพาะโครงการที่ Admin ผูกกับบัญชีลูกค้า พร้อมข้อมูลสรุป เช่น

- รหัสและชื่อโครงการ
- ประเภทโครงการ
- สถานะโครงการ
- เปอร์เซ็นต์ความคืบหน้ารวม
- ผู้ดูแลโครงการ
- จำนวนอัปเดตที่เผยแพร่แล้ว

### หน้ารายละเอียดโครงการ

ลูกค้าสามารถดูข้อมูลต่อไปนี้

- วันเริ่มงานและกำหนดส่งโดยประมาณ
- ผู้ดูแลโครงการ
- เปอร์เซ็นต์รวมของโครงการ
- ความคืบหน้าของแต่ละขั้นตอน
- Timeline อัปเดตหน้างานที่ Admin อนุมัติแล้ว
- รูปหน้างานและรายละเอียดของแต่ละอัปเดต
- เอกสารที่ตั้งค่าเป็น `ลูกค้าดูได้`
- รายการปัญหาที่เปิด `แสดงให้ลูกค้าเห็น`

### ข้อมูลที่ลูกค้าจะไม่เห็น

- อัปเดตสถานะฉบับร่าง
- อัปเดตที่รอ Admin ตรวจ
- อัปเดตที่ถูกส่งกลับแก้ไข
- เอกสารเฉพาะทีมงาน
- ปัญหาที่ไม่ได้เปิดให้ลูกค้าเห็น
- ข้อมูลของโครงการลูกค้ารายอื่น

## 4. โมดูลแดชบอร์ด

### Admin

แดชบอร์ด Admin ใช้ดูภาพรวมการทำงาน เช่น

- จำนวนโครงการทั้งหมด กำลังดำเนินงาน และเสร็จสิ้น
- เปอร์เซ็นต์ความคืบหน้าเฉลี่ย
- โครงการที่ต้องตรวจสอบหรือยังไม่มีผู้รับผิดชอบ
- อัปเดตฉบับร่างและรายการรออนุมัติ
- จำนวนบทความเผยแพร่และฉบับร่าง
- รายการติดต่อใหม่จากเว็บไซต์

### ผู้ตรวจหน้างาน

แดชบอร์ดผู้ตรวจแสดงเฉพาะงานที่เกี่ยวข้องกับตนเอง เช่น

- โครงการที่ได้รับมอบหมาย
- โครงการที่กำลังดำเนินงาน
- ขั้นตอนที่ต้องแก้ไข
- อัปเดตที่ถูกส่งกลับแก้ไข

### แนวทางใช้งาน

- Admin ควรตรวจรายการ `รอ Admin ตรวจ` เป็นประจำ
- ผู้ตรวจควรตรวจรายการ `ส่งกลับแก้ไข` ก่อนเริ่มอัปเดตใหม่
- ใช้แดชบอร์ดเป็นหน้าตรวจสุขภาพระบบประจำวัน ไม่ควรใช้แทนหน้ารายละเอียดโครงการ

## 5. โมดูลจัดการผู้ใช้งาน

### ผู้มีสิทธิ์

Admin เท่านั้น

### การเพิ่มผู้ใช้งาน

1. ไปที่ `จัดการผู้ใช้งาน`
2. กด `เพิ่มผู้ใช้งาน`
3. กรอกชื่อ ชื่อผู้ใช้ อีเมล และรหัสผ่านเริ่มต้น
4. เลือกบทบาท Admin ผู้ตรวจหน้างาน หรือลูกค้า
5. กดบันทึก
6. แจ้งรหัสเริ่มต้นผ่านช่องทางที่เชื่อถือได้
7. ผู้ใช้จะถูกบังคับให้เปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบ

### การเปลี่ยนบทบาท

1. ค้นหาบัญชีที่ต้องการ
2. เลือกบทบาทใหม่จากรายการ
3. กดปุ่มบันทึกสิทธิ์

ข้อจำกัด

- Admin ไม่สามารถลดสิทธิ์บัญชีที่กำลังใช้งานอยู่
- ระบบต้องมี Admin อย่างน้อย 1 บัญชี

### การจัดการความปลอดภัยบัญชี

กดปุ่มรูปโล่ที่ท้ายแถวผู้ใช้เพื่อเปิดหน้าความปลอดภัย จากหน้านี้ Admin สามารถ

- ตรวจจำนวนครั้งที่กรอกรหัสผิด
- ตรวจสถานะล็อกบัญชี
- ปลดล็อกบัญชี
- ตรวจว่าผู้ใช้ต้องเปลี่ยนรหัสผ่านหรือไม่
- ตรวจสถานะ 2FA
- ออกรหัสผ่านชั่วคราว โดยต้องยืนยันรหัสผ่าน Admin ของตนเอง

## 6. โมดูลจัดการโครงการ

### ผู้มีสิทธิ์

- Admin: สร้าง แก้ไข เก็บเข้าคลัง และกู้คืนโครงการ
- ผู้ตรวจหน้างาน: เปิดดูและทำงานเฉพาะโครงการที่ได้รับมอบหมาย

### การสร้างโครงการ

1. ไปที่ `โครงการลูกค้า`
2. กด `สร้างโครงการ`
3. กรอกรหัสโครงการและชื่อโครงการ
4. เลือกประเภทงาน
5. กรอกที่อยู่ วันเริ่มงาน และวันสิ้นสุดโดยประมาณ
6. เลือกสถานะเริ่มต้น
7. เลือกผู้ดูแลโครงการ
8. เลือกลูกค้าอย่างน้อย 1 บัญชี
9. กรอกข้อมูลสรุป แล้วบันทึก

### ประเภทโครงการ

- สร้างบ้าน
- รีโนเวท
- บิวท์อิน
- ออกแบบ
- งานอื่น ๆ

### สถานะโครงการ

- `เตรียมงาน`
- `กำลังดำเนินงาน`
- `พักงาน`
- `เสร็จสิ้น`

### คลังโครงการ

- การเก็บเข้าคลังเป็น Soft Delete ข้อมูล Timeline และไฟล์ยังอยู่ครบ
- Admin สามารถเปิด `คลังโครงการ` และกู้คืนรายการได้
- การเก็บเข้าคลังไม่ใช่การลบไฟล์ออกจาก Google Drive

## 7. โมดูลขั้นตอนงานและเปอร์เซ็นต์ความคืบหน้า

### ผู้มีสิทธิ์

- Admin: สร้าง แก้ไข ลบขั้นตอน และปรับความคืบหน้า
- ผู้ตรวจหน้างาน: เสนอความคืบหน้าผ่านอัปเดตหน้างานของโครงการที่ได้รับมอบหมาย

### การกำหนดขั้นตอน

แต่ละขั้นตอนประกอบด้วย

- ชื่อและรายละเอียดขั้นตอน
- น้ำหนักของขั้นตอนเป็นเปอร์เซ็นต์
- วันที่เริ่มและสิ้นสุดตามแผน
- ลำดับการแสดงผล

น้ำหนักรวมของทุกขั้นตอนต้องเท่ากับ 100% ก่อนระบบจะคำนวณเปอร์เซ็นต์รวมอัตโนมัติ

### สูตรคำนวณ

```text
เปอร์เซ็นต์ที่ขั้นตอนสร้างให้โครงการ = น้ำหนักขั้นตอน x ความคืบหน้าขั้นตอน / 100
เปอร์เซ็นต์รวมโครงการ = ผลรวมของทุกขั้นตอน
```

ตัวอย่าง

| ขั้นตอน | น้ำหนัก | ความคืบหน้า | ผลต่อโครงการ |
|---|---:|---:|---:|
| ฐานราก | 20% | 100% | 20% |
| โครงสร้าง | 40% | 50% | 20% |
| สถาปัตยกรรม | 40% | 10% | 4% |
| รวม | 100% | - | 44% |

### ผลการตรวจ

- `ยังไม่ได้ตรวจ`
- `ผ่านการตรวจ`
- `ไม่ผ่านการตรวจ`
- `กำลังแก้ไขงาน`

### การลดเปอร์เซ็นต์

ระบบอนุญาตให้ลดเปอร์เซ็นต์เมื่อพบปัญหาหน้างาน แต่ต้องระบุเหตุผล โดยระบบจะ

1. บันทึกเปอร์เซ็นต์เดิมและเปอร์เซ็นต์ใหม่
2. บันทึกผลการตรวจและเหตุผล
3. ปรับสถานะขั้นตอนเป็น `ต้องแก้ไข` เมื่อไม่ผ่านหรืออยู่ระหว่างแก้งาน
4. คำนวณเปอร์เซ็นต์รวมโครงการใหม่

ข้อควรระวัง: ขั้นตอนที่มีประวัติความคืบหน้าแล้วไม่สามารถลบได้ ให้แก้ชื่อหรือน้ำหนักแทน

## 8. โมดูลอัปเดตหน้างานและการอนุมัติ

### ผู้มีสิทธิ์

- ผู้ตรวจหน้างาน: สร้าง แก้ไข และส่งตรวจในโครงการที่ได้รับมอบหมาย

- ลูกค้า: ดูเฉพาะรายการที่อนุมัติแล้ว

### ข้อมูลในอัปเดต

- หัวข้อและรายละเอียดงาน
- หมวดงานหรือ Stage
- ขั้นตอนโครงการที่เกี่ยวข้อง
- เปอร์เซ็นต์ที่เสนอ
- ผลการตรวจ
- เหตุผลการปรับเปอร์เซ็นต์
- วันและเวลาที่ปฏิบัติงานจริง
- รูปภาพสูงสุด 10 รูปต่อครั้ง

### Stage ของงาน

- สำรวจและเตรียมพื้นที่
- ออกแบบและอนุมัติแบบ
- จัดเตรียมวัสดุ
- งานโครงสร้าง
- งานสถาปัตยกรรม
- งานตกแต่งและบิวท์อิน
- ตรวจสอบและเก็บงาน
- ส่งมอบโครงการ

### สถานะอัปเดต

| สถานะ | ความหมาย | ลูกค้าเห็นหรือไม่ |
|---|---|---|
| ฉบับร่าง | ผู้สร้างยังแก้ไขได้ | ไม่เห็น |
| รอ Admin ตรวจ | ส่งให้ Admin พิจารณาแล้ว | ไม่เห็น |
| ส่งกลับแก้ไข | Admin ระบุสิ่งที่ต้องแก้ | ไม่เห็น |
| อนุมัติและเผยแพร่แล้ว | ข้อมูลถูกนำไปคำนวณและเผยแพร่ | เห็น |

### Workflow มาตรฐาน

1. ผู้ตรวจสร้างอัปเดตและเลือก `บันทึกฉบับร่าง` หรือ `ส่งให้ Admin ตรวจ`
2. เมื่อส่งตรวจ ระบบแจ้ง Admin
3. Admin ตรวจข้อความ รูป วันเวลา ขั้นตอน เปอร์เซ็นต์ และผลการตรวจ
4. หากถูกต้อง Admin กดอนุมัติ
5. ระบบอัปเดตเปอร์เซ็นต์ขั้นตอนและโครงการ
6. ระบบเผยแพร่รายการให้ลูกค้าและส่งการแจ้งเตือน
7. หากข้อมูลไม่ครบ Admin กรอกเหตุผลและกดส่งกลับแก้ไข
8. ผู้ตรวจแก้รายการเดิมและส่งตรวจอีกครั้ง

ข้อควรระวัง

- เมื่อส่งตรวจแล้ว ผู้ตรวจจะแก้ไขไม่ได้จนกว่า Admin จะส่งกลับ
- เปอร์เซ็นต์มีผลจริงหลัง Admin อนุมัติ
- ควรตรวจว่ารูปไม่มีข้อมูลส่วนบุคคลหรือเอกสารสำคัญติดอยู่โดยไม่ตั้งใจ

## 12. โมดูลโปรไฟล์และ 2FA

### ผู้มีสิทธิ์

ผู้ใช้งานทุกบทบาท

### ข้อมูลโปรไฟล์

ผู้ใช้สามารถแก้ไข

- ชื่อ
- ชื่อผู้ใช้
- อีเมล
- LINE Recipient ID เมื่อใช้งานแจ้งเตือน LINE
- รูปโปรไฟล์
- รหัสผ่าน

### การเปิด 2FA

1. เปิดหน้า `โปรไฟล์ผู้ใช้งาน`
2. ไปส่วน `การยืนยันตัวตนสองชั้น`
3. กรอกรหัสผ่านปัจจุบัน
4. กด `เริ่มตั้งค่า 2FA`
5. เพิ่ม Setup Key ใน Google Authenticator, Microsoft Authenticator หรือ 1Password
6. กรอกรหัส 6 หลักเพื่อยืนยัน
7. บันทึก Recovery Codes ทั้ง 8 รหัสไว้ในที่ปลอดภัย

### การ Login หลังเปิด 2FA

1. กรอกชื่อผู้ใช้และรหัสผ่านตามปกติ
2. กรอกรหัส 6 หลักจาก Authenticator
3. หากไม่มีโทรศัพท์ ให้ใช้ Recovery Code หนึ่งรหัสแทน

Recovery Code แต่ละรหัสใช้ได้หนึ่งครั้ง และระบบไม่แสดงซ้ำหลังออกจากหน้าตั้งค่า

ข้อสำคัญ: หากสูญเสียทั้งอุปกรณ์ Authenticator และ Recovery Codes ระบบปัจจุบันยังไม่มีปุ่ม Reset 2FA จากหน้าจัดการผู้ใช้ ต้องส่งต่อให้ผู้ดูแลเทคนิคตรวจยืนยันตัวตนและดำเนินการกู้คืนตามนโยบายของบริษัท

### การปิด 2FA

ต้องกรอกรหัสผ่านปัจจุบัน พร้อมรหัส Authenticator หรือ Recovery Code ที่ยังใช้ได้

## 21. โมดูลไฟล์ รูปภาพ วิดีโอ และ Google Drive

### การทำงานปัจจุบัน

- ระบบรองรับ Local Storage และ Google Drive ตามค่าที่กำหนด
- รูปภาพถูกปรับขนาดและแปลงเป็น WebP เมื่อระบบรองรับ
- ไฟล์มีค่า SHA-256 สำหรับตรวจสอบความถูกต้อง
- ไฟล์สำคัญถูกกำหนดเป็น Private และเปิดผ่าน Controller ที่ตรวจสิทธิ์
- ระบบรองรับ Quarantine และ Malware Scan เมื่อเปิดใช้ ClamAV บน Production

### แนวทางจัดเก็บ

- ใช้โฟลเดอร์ Drive เฉพาะของระบบ
- ใช้ Service Account และสิทธิ์ `drive.file`
- ห้ามเก็บ Credential ใน Git
- เอกสารลูกค้าและรูปหน้างานต้องเปิดผ่านระบบ ไม่ควรแชร์ลิงก์ Drive แบบ Public
- สำรองฐานข้อมูลและไฟล์ไปยังปลายทางที่เข้ารหัสอีกหนึ่งชุด

### การลบข้อมูล

- การลบรูปจากรายการที่ระบบจัดการจะลบ Stored File ที่เกี่ยวข้อง
- การเก็บโครงการเข้าคลังไม่ลบไฟล์
- ควรตรวจความสัมพันธ์ของไฟล์ก่อนลบรายการถาวร

## 22. SOP งานหลัก

### SOP A: รับลูกค้าใหม่จนเริ่มโครงการ

1. ตรวจ Lead จากเว็บไซต์
2. ติดต่อและบันทึกผล
3. สร้างบัญชีลูกค้าหรือแปลง Lead เป็นโครงการ
4. ส่งรหัสชั่วคราวให้ลูกค้าอย่างปลอดภัย
5. สร้างโครงการและผูกบัญชีลูกค้า
6. มอบหมายผู้ตรวจหรือผู้ดูแล
7. กำหนดขั้นตอนและน้ำหนักรวม 100%
8. อัปโหลดเอกสารที่จำเป็นพร้อมกำหนดสิทธิ์
9. ให้ลูกค้าทดลอง Login เปลี่ยนรหัส และเปิด 2FA

### SOP B: อัปเดตหน้างานประจำวัน

1. ผู้ตรวจเปิดโครงการที่ได้รับมอบหมาย
2. ตรวจขั้นตอนที่กำลังทำ
3. สร้างอัปเดตพร้อมรูป วันเวลา และเปอร์เซ็นต์ที่เสนอ
4. ระบุผลตรวจและเหตุผลเมื่อจำเป็น
5. ส่งให้ Admin ตรวจ
6. Admin ตรวจความถูกต้อง
7. อนุมัติ หรือส่งกลับพร้อมเหตุผล
8. ตรวจว่าลูกค้าได้รับการแจ้งเตือนหลังอนุมัติ

### SOP C: งานไม่ผ่านการตรวจ

1. เลือกผลตรวจ `ไม่ผ่านการตรวจ`
2. ปรับเปอร์เซ็นต์ตามสภาพจริง
3. ระบุเหตุผลอย่างชัดเจน
4. เปิดรายการปัญหาและมอบหมายผู้แก้
5. แนบรูปก่อนแก้
6. หลังแก้ เปลี่ยนเป็น `รอตรวจรับ`
7. ตรวจซ้ำและอัปเดตผล
8. ปิดปัญหาเมื่อผ่านการตรวจ

### SOP D: เผยแพร่บทความหรือแบบบ้าน

1. บันทึกเป็นฉบับร่าง
2. ตรวจข้อความ รูป Alt Text และ SEO
3. เปิดหน้าพรีวิว
4. ตรวจ Desktop และ Mobile
5. เปลี่ยนสถานะเป็นเผยแพร่
6. เปิดหน้าจริงและตรวจลิงก์

### SOP E: ผู้ใช้เข้าไม่ได้

1. ตรวจว่าเลือกหน้า Login ตรงกับบทบาท
2. ตรวจชื่อผู้ใช้หรืออีเมล
3. ตรวจสถานะล็อกในหน้าความปลอดภัยผู้ใช้
4. ปลดล็อกหากจำเป็น
5. ใช้ลืมรหัสผ่าน หรือออกรหัสชั่วคราว
6. หากเปิด 2FA ให้ใช้ Authenticator หรือ Recovery Code
7. หากไม่มีทั้งสองอย่าง ให้ผู้ดูแลตรวจยืนยันตัวตนก่อนดำเนินการเพิ่มเติม

## 23. การแก้ปัญหาเบื้องต้น

| อาการ | สาเหตุที่พบบ่อย | แนวทางตรวจสอบ |
|---|---|---|
| Login ไม่ได้ | เลือก Portal ผิด รหัสผิด บัญชีถูกล็อก | ตรวจบทบาท รอ 60 วินาที หรือให้ Admin ปลดล็อก |
| ไม่ได้รับอีเมลรีเซ็ตรหัส | SMTP ยังไม่ตั้งค่า หรืออีเมลไม่ตรง | ตรวจอีเมลและค่า Mail ใน Production |
| ไม่มีรหัส 2FA | เวลาโทรศัพท์ไม่ตรง หรือเลือกบัญชีผิด | เปิดเวลาอัตโนมัติ ตรวจบัญชีใน Authenticator หรือใช้ Recovery Code |
| ลูกค้าไม่เห็นอัปเดต | รายการยังไม่ถูกอนุมัติ | ตรวจสถานะต้องเป็น `อนุมัติและเผยแพร่แล้ว` |
| เปอร์เซ็นต์รวมไม่เปลี่ยน | น้ำหนักขั้นตอนไม่ครบ 100% หรือรายการยังไม่อนุมัติ | ตรวจน้ำหนักและสถานะอัปเดต |
| ลดเปอร์เซ็นต์ไม่ได้ | ไม่ได้กรอกเหตุผล | ระบุเหตุผลการลดหรือสาเหตุที่ไม่ผ่านตรวจ |
| ผู้ตรวจไม่เห็นโครงการ | ยังไม่ได้มอบหมายเป็นผู้ดูแล | Admin แก้โครงการและเลือกผู้ดูแล |
| ลูกค้าเปิดเอกสารไม่ได้ | เอกสารเป็นเฉพาะทีมงาน | เปลี่ยน Visibility เป็น `ลูกค้าดูได้` หลังตรวจเนื้อหา |
| รูปอัปโหลดไม่ได้ | ไฟล์ใหญ่หรือชนิดไฟล์ไม่รองรับ | ใช้ JPG PNG หรือ WebP และลดขนาดก่อนอัปโหลด |
| รูปหน้าบ้านไม่เปลี่ยน | Cache หรือข้อมูลยังเป็นฉบับร่าง | Refresh หน้า ตรวจสถานะเผยแพร่ และล้าง Cache เมื่อ Deploy |
| Form ติดต่อไม่เข้า | API หรือ Backend ไม่ทำงาน | ตรวจ Backend, API URL และ Log ของระบบ |
